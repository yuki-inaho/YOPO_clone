# YOPO RGB-D — RTX 5090 / CUDA 12.8 environment

The active `rgb-d` branch is configured for a repo-local uv environment on an
NVIDIA GeForce RTX 5090 (compute capability `sm_120`). It uses Python 3.10,
PyTorch 2.8.0 + CUDA 12.8, and MMCV 2.2.0 with CUDA operators.

## Setup

From the repository root:

```bash
just setup
just env-doctor
```

`just setup` runs `uv sync` and writes a `.pth` file so the renamed
`yopo` package resolves from the repository root. The first run downloads the
CUDA-enabled PyTorch runtime; later runs are incremental.

Expected `just env-doctor` output includes:

```text
torch 2.8.0+cu128 | cuda 12.8
torchvision 0.23.0+cu128
mmcv 2.2.0
cuda_available True
device NVIDIA GeForce RTX 5090
```

## MMCV wheel

`pyproject.toml` pins the full CUDA-ops wheel
`mmcv-2.2.0-0sm120t280-cp310-cp310-linux_x86_64.whl` from the
`yuki-inaho/mmcv` `cu128-wheels-v0.1` release. It is compiled specifically for
`sm_120` and Torch 2.8.0 + cu128, so do not replace it with the generic PyPI
source distribution or a wheel for another Torch/CUDA/compute-capability
combination.

The RGB-D and rotated-box paths require these CUDA operations, including NMS
and differentiable rotated IoU. Verify them without downloading data:

```bash
uv run python -c "from mmcv.ops import nms, diff_iou_rotated_2d; print('MMCV CUDA ops import OK')"
```

## Training and inference

The usual project commands remain unchanged:

```bash
just gen-synthetic
just smoke-train
just smoke-infer
just train <config>
```

The legacy `docs/CU121_TRAINING.md` describes the original L4/cu121 smoke
workflow. Use this document and the active `pyproject.toml` for the RTX 5090
environment instead.
